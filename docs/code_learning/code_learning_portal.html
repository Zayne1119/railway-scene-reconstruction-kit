ARCHITECTURE

不是“一键黑盒”

railway_recon.cli:main 提供 50 多个显式命令，没有统一 DAG 编排器。每一步的输入、输出和失败状态都要由操作者负责串联。

AUTHORITATIVE PATH

钢轨链路最完整

钢轨已经具备候选、人工接受、TrackGraph、连续网格、注册表映射和发布门禁；局部候选绝不能直接进入权威 Mesh。

CAPABILITY BOUNDARY

非轨道资产仍以审核布局为主

站台、雨棚、接触网和照片解释资产可生成参数化几何，但完整自动分割、专业分类和多平面恢复在当前公开代码中并不完整。

SOURCE OF TRUTH

“final.glb”不是权威证明

权威资格来自通过审计的图、全 accepted 冻结注册表、Mesh/关系 QA，以及模型—注册表—资产集合的精确哈希绑定。

SYSTEM CONTRACTS

十个必须守住的不变量

换算法可以，换场景可以；这些合同不能被绕过。它们正是项目从“能显示”走向“可交付、可追溯”的核心。

INV-01所有项目输出必须留在项目根目录内。
INV-02局部候选不是权威几何，未复核来源不得进入 pass 图。
INV-03TrackGraph 必须绑定当前 camera 和配置哈希。
INV-04错误轨道宁可显式断开，也不能为了连续被强制连接。
INV-05推断区间必须保持 rule_inferred，不能伪装 observed。
INV-06每个可见 Mesh 对象必须具有唯一、可查询的资产身份。
INV-07发布注册表只能包含 accepted 资产。
INV-08Gate 只认显式 pass，模糊状态一律阻断。
INV-09Web 交付必须绑定模型、注册表和资产集合哈希。
INV-10无 CRS、垂直基准和独立点时，只能声明内部拟合精度。
