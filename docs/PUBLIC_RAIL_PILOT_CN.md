# 公开训练点云：候选提取与数字标签诊断

本轮已从字段适配推进到真实公开点云的自动候选提取、两组对照、完整评价与定位图。只使用 SemanticRail3D-V2 的 `cloud180_Seg1.laz`，没有客户数据，没有运行公开或合成封存测试。

这是一个公开 train 片段上的开发试跑，不是完整轨道建模、连接关系验证、独立泛化或测量精度实验。

## 输入与隔离

- 907,816 个点，SHA256 为 `b81701df0f2f07dff14fe956f4b507c9ea719f416d99550da8e550b41ef36367`。
- 固定 [V2 来源](https://zenodo.org/records/15641832)、官方说明 commit、六份本地元数据哈希及 train/val/test/removed 声明；确认该成员属于保留 train，父 cloud 不进入 val/test。没有下载完整归档。
- 提取函数只接收只读 XYZ 数组、固定策略和模式。适配器会解码标签并统计字段，但分类、实例 ID 和任何标签筛选子集都不传给提取器。
- 两组预测先保存并写入 `prediction_lock.json`，之后才进行数字标签对照。该锁是内部执行顺序记录，不是外部盲测或预注册。
- 输入、数字标签、候选、预测掩码及错误点索引分目录保存。所有点参与评价；图片为统一的 100,000 点确定性显示子样，使用完整 XY 范围。

## 两种模式

`height_prominence`：沿低高程窗口的 XY PCA 方向建立网格，根据局部高程突起和纵向支持提出线状候选。方向由 XYZ 推导，不伪造相机轨迹。

`paired_geometry`：使用完全相同的候选池，进一步按候选间距、高差和共同纵向支持选择配对。默认参数沿用通用几何规则；新增 PCA、网格资源限制等参数全部写入协议。不把候选位置拉到标称轨距，也不填补无观测支持的折线区间。

单一 PCA 方向、全局低高程窗及固定配对间距都有迁移限制。两组输出是可检查的几何假设，不是已确认钢轨身份或修复后的模型。

## 实际结果与失败原因

局部模式提取 **5 条线状候选、14,020 个候选点**；配对模式返回 **0 个候选点**，完整保留空结果。

候选横向拟合位置约为 -11.192、-0.451、1.295、3.416、5.200 m。其中两组相邻间距约 **1.747 m、1.784 m**，均大于原规则上界 **1.65 m**（范围 1.35–1.65 m），没有任何组合进入间距相容的配对候选表。因此本次为空的直接原因在配对间距条件，不能仅凭概括性的 `no_pair_with_shared_support` 将其归因于缺少共同观测。

这些数值是拟合中心位置差，不是现场净轨距；不能据此直接确认线路轨距制式或将参数改成某一制式后称已验证。本轮没有根据结果回调阈值，下一版应把间距假设显式列入迁移对照。

## 为什么暂不称“钢轨准确率”

目前查阅的官方资料明确说明 class 0 是未分类背景，但未找到 Rail 名称与数字 ID 的显式对应。固定数字类 `1` 仅作为探针；它有 29,876 点。不是根据提取结果选出表现最好的类别，也不靠候选与该类重合来反推官方编号。

| 模式 / 口径 | TP | FP | FN | Precision | Recall | F1 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 局部 / 全点数字类 1 | 12,830 | 1,190 | 17,046 | 0.9151 | 0.4294 | 0.5846 |
| 局部 / 非 0 类 | 12,830 | 0 | 17,046 | 1.0000 | 0.4294 | 0.6009 |
| 配对 / 全点数字类 1 | 0 | 0 | 29,876 | 不可定义 | 0 | 0 |
| 配对 / 非 0 类 | 0 | 0 | 29,876 | 不可定义 | 0 | 0 |

局部模式选中的 1,190 个非目标点全部属于未分类的 0；它们不是独立确证的非钢轨。排除它们会使 Precision 变成 1，不能把这个辅助口径宣传为钢轨精度 100%。两种口径、全部数字类选中计数、所有 TP/FP/FN 及未分类选中点索引均保留。完整语义身份、连接关系和绝对精度依然不可评价。

映射核查边界和来源见 [数字类别契约](PUBLIC_RAIL_REFERENCE_CN.md)。该缺口需要有来源的映射或其他明确标注的公开子任务，不转化成用户逐点标注工作。

## 复现

工具包根目录下执行；输出必须为新路径，已有结果一律不覆盖。

```powershell
.\.venv\Scripts\python.exe scripts/run_public_rail_pilot.py init --output benchmarks/protocols/public-rail-pilot-v1.json
.\.venv\Scripts\python.exe scripts/run_public_rail_pilot.py run --input ../work/paper_public_data_p1/cloud180_Seg1.laz --metadata-directory ../work/paper_public_data_p1 --protocol benchmarks/protocols/public-rail-pilot-v1.json --output benchmarks/local/paper-public-rail/pilot-v1
```

已经存在协议时直接复用它，并为重跑选择新的输出目录。程序无网络下载逻辑；它核验此前独立取得的公开元数据和完整小成员。协议固定样本、角色、数字参考契约、参数与两种模式，不允许悄悄切换为测试或客户文件。

结果位于 `benchmarks/local/paper-public-rail/pilot-v1/`：`report.json`/`report.md`、`metrics.csv`、`comparison.png`、`inputs/xyz.npz`、`ground_truth/classification.npz`、两组 `predictions/`、`evaluation/` 和哈希清单。完整运行的 19 份产物、236 份源码/资源/依赖绑定和 4 份预测锁绑定均复核一致，错误索引数量与混淆计数一致。
