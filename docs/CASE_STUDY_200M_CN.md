# 脱敏案例：200 m 站场重点区精细化

本案例用于说明工具链如何从小样段扩展到重点区。内容已去除站名、坐标、照片索引、客户信息和现场文件名，不包含可用于还原现场位置的原始数据。

## 1. 案例目标

在约 200 m 的站场重点区内，建立一个可以查询资产、区分证据等级、支持 Web 查看和引擎导入的完整场景。重点对象包括：

- 多股道钢轨、轨枕和道床；
- 站台面、边缘、安全构造和排水；
- 雨棚柱、柱帽、横纵梁、屋面段和吊顶；
- 楼梯、电梯和栏板交界；
- 接触网支柱、腕臂、线索和吊弦；
- 铁路侧可见立面、门窗和玻璃；
- 标牌、箱柜、围栏和线路外侧小资产；
- 不可见背面的低置信体块。

## 2. 数据特点

- 点式观测沿铁路走廊采集，线路方向覆盖较好；
- 建筑和设备背向线路的一侧观测不足；
- 全景可补充可见立面和标识，但不能替代测量；
- 细线、玻璃、屋面边缘和复杂交界更容易缺点或产生噪声；
- 未确认坐标基准时，评价仅限于内部点—模型拟合。

这些特点在多数移动采集铁路项目中具有代表性，因此案例的重点不是复制尺寸，而是复制决策流程。

## 3. 实施过程

### 3.1 先做 20–50 m Pilot

Pilot 先验证：

- 点云和相机轨迹方向；
- 钢轨候选和轨距约束；
- 竖直候选的连续性；
- 全景投影是否可用于语义复核；
- 接触网和雨棚柱的分类边界；
- 资产 ID、注册表和预览页面链路。

这一步避免了在 200 m 上重复放大错误。

### 3.2 轨道系统

采用纵向分段拟合轨头点，再由铁路截面和轨距约束生成可编辑钢轨、轨枕和道床。重点不是提高面数，而是保证：

- 两股钢轨属于同一轨道且不重叠；
- 轨头高程连续；
- 段界方向和平移连续；
- 轨枕垂直于局部线路方向；
- 道床不吞没钢轨或悬空。

实际复核曾发现“局部轨道断裂”和“两套轨道叠在一起”的视觉问题。这类问题不能靠 Mesh 平滑解决，必须回到资产拓扑、段界和版本叠加关系处理。

### 3.3 站台与雨棚

站台不能用一个平面强行贯穿整个重点区，而应按证据分段拟合高程和边界。雨棚不能只生成连续薄板，而需要恢复：

- 多个真实屋面段；
- 坡面、屋脊、檐口和排水；
- 柱网、柱帽、支座和梁；
- 屋面与梁柱的真实接触；
- 楼梯、电梯和栏板开口。

复核暴露过的典型问题包括：屋面破片、共面闪烁、柱顶未接触屋面、楼梯顶层平台缺失和栏板接口错误。经验是：从屋面俯视和雨棚下近景两种方向同时验收，单一全景视角会漏掉大部分问题。

### 3.4 接触网与竖直资产

先提取竖直候选，再结合位置、截面、照片和铁路关系区分：

- 接触网支柱；
- 雨棚柱；
- 建筑边缘；
- 信号/通信/电力杆件；
- 误检。

接触网线索按“观测线段优先、规则补全显式降级”的原则处理。单纯为了画面连续而补出的线段必须标为 `rule_inferred`，并允许在页面中关闭。

### 3.5 站房可见立面

照片用于恢复铁路侧可见立面轮廓、门窗、玻璃和标识。处理边界：

- 照片可确认存在，但不能直接给出测量精度；
- 遮挡后结构不连续外推；
- 背向铁路一侧仅保留低置信体块；
- Web 中区分点拟合、照片解释和低置信背面。

### 3.6 缺口闭环

将点式证据与当前模型距离栅格化，输出高缺口网格。每格必须归为：

- 已建资产但拟合不足；
- 漏建资产；
- 植被/临时物/噪声；
- 不属于交付范围；
- 数据不足，待补采；
- 已由低置信体块表达。

缺口比例下降不是唯一目标。错误地用大平面覆盖缺口，会让数值变好却使模型更不可信。

## 4. 证据和模型分层

案例最终采用四级表达：

- `observed`：点式几何直接支持；
- `photo_interpreted`：全景确认可见形体；
- `rule_inferred`：专业规则和邻接关系补全；
- `unsupported`：不可见或无法确认的占位。

clean 主模型优先包含已接受资产；规则候选和不确定证据可另建图层。这样既保证展示完整性，也不牺牲可追踪性。

## 5. 关键错误与修复逻辑

| 表面现象 | 根因 | 正确修复 |
|---|---|---|
| 铁轨断裂 | 分段端点和切向未闭合 | 重算段界拓扑和切向，不用遮挡块掩盖 |
| 两套轨道压在一起 | 新旧版本同时进入场景 | 清理层和注册表，保留单一 accepted 资产 |
| 站台缝隙闪烁 | 共面重叠或端点未焊接 | 合并/错开面层并重做边界 |
| 屋面大量破面 | 面绕序、重叠薄片或错误三角化 | 重建封闭屋面段并统一法线 |
| 柱子未顶到屋面 | 柱高与梁底/柱帽分别拟合 | 用支持关系驱动柱顶和梁底连接 |
| 楼梯出口异常 | 顶层平台与开口分开建模 | 以完整通行拓扑重建平台、栏板和洞口 |
| 细线远处消失 | 真实直径过细或材质/LOD不合适 | 分离可视化配置，保留真实几何语义 |
| 页面点击错资产 | 旋转后拾取或节点ID不同步 | 以注册表 assetId 绑定节点并做旋转后测试 |

## 6. 形成的可复用方法

1. 先小样、后重点区、再全线；
2. 坐标、照片投影和资产字典必须在 Pilot 冻结；
3. 站台和屋面按真实段重建，不用贯穿面；
4. 轨道连续性要在资产/拓扑层解决；
5. 证据等级写入注册表，而不是只用颜色口头说明；
6. 缺口闭环需要逐格定性，不能只追求低残差；
7. clean 模型和 candidate/evidence 图层分开；
8. Mesh 验收必须开启背面剔除并检查近景；
9. UE/Web 验收是交付质量，不等于测量正确性；
10. 没有控制基准时只报告内部拟合。

## 7. 如何套用到新项目

可复用：

- 数据合同；
- 项目目录和运行清单；
- 20–50 m Pilot 门禁；
- 资产分类框架；
- 证据等级；
- 参数化建模顺序；
- 缺口审计方法；
- Mesh、UE、Web 验收表。

不可直接复制：

- 坐标和局部原点；
- 站台、雨棚和站房尺寸；
- 候选编号和人工分类结果；
- 接触网支柱位置；
- 相机姿态修正；
- 现场阈值和照片引用；
- 旧项目最终模型。

新项目必须从输入审计和 Pilot 重新开始。直接套用旧尺寸，通常会比重新拟合更快地产生“看起来完整、实际错误”的模型。

## 8. 案例结论

200 m 精细化案例证明这条生产路线可以把不完整走廊观测整理成结构化、可查询、可交付的铁路场景；同时也证明模型质量的主要风险不在“有没有面”，而在证据、拓扑、段界和交界关系。新项目应复制的是流程、门禁和可追踪机制，而不是旧项目的几何参数。
