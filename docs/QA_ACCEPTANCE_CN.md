# 质量验收与交付规范

本规范把“模型是否可信”拆成数据、几何、语义、Mesh、引擎、Web 和安全七道门。任一门失败时不得把最终包标记为 accepted。

## 1. 验收原则

1. 自动检查与人工检查都必须执行；
2. 自动 `passed` 只覆盖已实现的检查项；
3. 同一工程师不应独立完成建模和最终视觉签字；
4. clean 主模型和 candidate/evidence 图层分开验收；
5. 所有错误都要有修复、接受风险或延期三种结论之一；
6. 任何重新导出都使旧截图失效，需要重新执行相应门禁。

## 2. Gate 0：输入与可追踪性

必检项：

- [ ] `project.json` 通过 Schema；
- [ ] 点云、相机 CSV 存在且哈希已记录；
- [ ] 点云单位、轴向、scale/offset 已检查；
- [ ] 相机索引和时间递增，无未解释重复；
- [ ] 照片缺失量及影响区间已记录；
- [ ] CRS、垂直基准和控制点状态明确；
- [ ] 输入没有被流水线覆盖；
- [ ] 当前 Git commit、配置哈希和工具版本进入 manifest。

基础命令：

```powershell
railway-recon validate --project projects/sample_line/project.json
railway-recon audit --project projects/sample_line/project.json --full-hash
railway-recon qa --project projects/sample_line/project.json
```

## 3. Gate 1：Pilot 几何

在 20–50 m Pilot 中至少检查六个固定视角：

1. 全景斜视；
2. 沿线路正向；
3. 沿线路反向；
4. 站台/轨道侧视；
5. 雨棚屋面俯视；
6. 雨棚下方或结构交界近景。

### 3.1 轨道系统

- [ ] 两股钢轨未压在一起；
- [ ] 无明显中断、错接、反折或跨轨连接；
- [ ] 段界连续，轨头高度和方向平顺；
- [ ] 轨距检查使用轨头内侧或约定测点，方法一致；
- [ ] 轨枕间距、方向合理，无大面积穿插；
- [ ] 道床肩部、边界和厚度合理；
- [ ] 误差按轨道和区段分别统计，而非只给全局均值。

### 3.2 站台系统

- [ ] 站台按证据分段拟合，不用单一平面强贯全线；
- [ ] 站台边缘与轨道保持合理关系；
- [ ] 分缝没有裂开、重叠或闪烁；
- [ ] 安全线、盲道和边缘构造不悬空；
- [ ] 楼梯、电梯和栏板开口真实存在且连接闭合。

### 3.3 雨棚系统

- [ ] 柱脚落在平台或基础上；
- [ ] 柱顶通过柱帽/支座连接梁或屋面；
- [ ] 无重复柱、错位柱、悬空柱；
- [ ] 横梁、纵梁的梁深和搭接关系一致；
- [ ] 屋面分成证据支持的真实段，不强制贯穿；
- [ ] 屋脊、坡面、檐口、封板、排水沟无明显破面；
- [ ] 吊顶和屋面不是互相穿插的共面片。

### 3.4 接触网与线路设备

- [ ] 支柱型号、截面、方向和基础合理；
- [ ] 腕臂、定位器、绝缘子与支柱关系正确；
- [ ] 接触线、承力索连续且没有突然跨轨；
- [ ] 吊弦不重复、不悬空、不反接；
- [ ] 规则推断线段有低置信标识；
- [ ] 信号、通信、电力和误检没有被混为同类。

## 4. Gate 2：证据与语义

- [ ] 每个资产有证据等级；
- [ ] 点云支持不足的资产未标记为 observed；
- [ ] 照片解释资产有逻辑证据引用；
- [ ] 规则补全资产有规则 ID 和限制；
- [ ] 不可见背面明显标为 unsupported 或 rule_inferred；
- [ ] 所有低置信候选有人工结论；
- [ ] 资产类型、存在性和拓扑由铁路专业人员抽样复核；
- [ ] 页面可以按证据等级筛选或着色。

建议抽样覆盖：直线轨道、复杂轨道、站台边缘、雨棚交界、楼梯/电梯、接触网节点、线路外侧小资产和遮挡区。

## 5. Gate 3：内部拟合与绝对精度

### 5.1 内部拟合

每类核心资产至少报告：样本数、覆盖率、MAE、RMSE、P50、P90、P95。距离采样方法、法向/欧氏距离和异常值规则必须写清楚。

内部拟合回答的是：模型是否贴合当前观测。

### 5.2 绝对精度

只有以下条件满足才可启用：

- CRS/EPSG 已确认；
- 垂直基准已确认；
- 有独立检查点、测量成果或同等级真值；
- 独立真值未参与模型拟合；
- 坐标变换和误差传播有记录。

否则报告必须设置 `absolute_precision_ready: false`，并使用统一限制语句：

> 本报告数值为模型相对于输入点式观测的内部拟合结果，不代表绝对测量精度。

## 6. Gate 4：Mesh 质量

### 6.1 自动检查

- [ ] 非有限顶点数为 0；
- [ ] 零面积/退化面数为 0；
- [ ] 完全重复面数为 0；
- [ ] 不应存在的共面重叠已清理；
- [ ] 法线存在且绕序一致；
- [ ] 材质槽有效；
- [ ] 对象变换已按导出策略应用；
- [ ] 资产 ID 未在清理过程中丢失；
- [ ] 模型边界和单位符合配置；
- [ ] 三角面数和对象数记录在 manifest。

### 6.2 人工检查

开启背面剔除，检查：

- 屋面、吊顶、站台和墙面是否突然消失；
- 薄片法线是否反向；
- 两层面是否因距离过近产生闪烁；
- 透明玻璃是否与不透明结构排序冲突；
- 长构件段界是否产生亮缝；
- 细线和小构件在远近视角是否稳定。

### 6.3 不允许通过的缺陷

- 大面积破面或面片爆炸；
- 轨道重叠、断裂或跨轨错误；
- 柱子未接触屋面/梁；
- 楼梯无顶层平台或栏板封死出口；
- 站台面悬空、裂缝或交叠；
- 同一位置存在两个版本的资产；
- 通过关闭背面剔除来掩盖错误法线。

## 7. Gate 5：Blender/UE 验收

导入全新空场景，不能依赖建模电脑的缓存或已有材质。

### 7.1 基础导入

- [ ] 单位为米，整体尺度正确；
- [ ] Z-up/前向轴转换符合说明；
- [ ] 局部原点策略明确，避免大坐标浮点问题；
- [ ] GLB、FBX、OBJ 的边界尺寸相符；
- [ ] 显式法线和材质正确；
- [ ] 资产命名和层级可识别。

### 7.2 UE 专项

- [ ] 无明显闪面或 Z-fighting；
- [ ] 无因单面材质造成的大面积消失；
- [ ] 玻璃使用单独材质策略；
- [ ] 细线在目标视距下可见；
- [ ] Nanite 是否启用按资产类型决定，不是一键全开；
- [ ] 细线、透明材质和需要变形的资产单独评估 Nanite；
- [ ] 碰撞仅对业务需要的对象生成；
- [ ] LOD/HLOD 策略有性能记录；
- [ ] 目标硬件上完成帧率、显存和加载时间记录。

## 8. Gate 6：Web 验收

- [ ] 默认页面加载 clean 主模型；
- [ ] 模型错误时显示明确错误，不展示空白假成功；
- [ ] 旋转模型后点击仍选择正确资产；
- [ ] 高亮对象与信息面板 ID 一致；
- [ ] 可按 ID、类型、状态、证据等级和置信度筛选；
- [ ] candidate/evidence 图层默认状态符合发布策略；
- [ ] 模型/点证据对比使用同坐标、同镜头、同尺度；
- [ ] 统计面板数据来自当前注册表；
- [ ] 桌面端与移动端均通过；
- [ ] 局域网访问只绑定必要端口，并遵守内部网络规则。

性能验收至少记录：模型大小、首屏加载时间、峰值内存、目标设备帧率、拾取响应时间和失败浏览器。

## 9. Gate 7：发布包与安全

正式交付建议结构：

```text
release/
├─ models/
│  ├─ clean.glb
│  ├─ clean.fbx
│  ├─ clean.obj
│  └─ clean.mtl
├─ registry/
│  └─ asset_registry.json
├─ reports/
│  ├─ quality_report.json
│  ├─ mesh_audit.json
│  └─ limitations.md
└─ manifest.json
```

发布前：

```powershell
railway-recon registry-check --project projects/sample_line/project.json
railway-recon qa --project projects/sample_line/project.json
railway-recon safety-check --root .
```

并人工确认 release 不包含：生产点云、全景、控制点、精确坐标、本机绝对路径、账号密钥、客户信息、未授权 HDRI/纹理或历史工作文件。

## 10. 验收记录模板

```markdown
## Release acceptance

- Project ID:
- Run ID:
- Git commit:
- Config hash:
- Clean model hash:
- Registry hash:
- Automated QA: PASS / FAIL
- Six-view review: PASS / FAIL
- UE/Blender import: PASS / FAIL
- Web interaction: PASS / FAIL
- Absolute precision ready: YES / NO
- Open risks:
- Accepted by role:
- Date:
```

任一项为 FAIL 时，只能发布为 review candidate，不能命名为 final。
