# 给接手 AI 的项目操作指令

目的：帮助单人操作者快速生成可编辑、可查看的铁路场景候选模型。优先推进真实出模与可见质量，不要把工作变成连续报表、打包或逐项让用户批准。

## 先恢复状态

1. 阅读根 README、`docs/NEWCOMER_HANDOFF_CN.md` 和本文件；检查当前目录、Git 状态与已有项目，保留不属于本任务的修改。
2. 若只是验证安装，从 `Railway.ps1 demo` 开始；已安装则 `demo -SkipSetup -NoStart`。合成演示不读客户文件。
3. 先做 `Railway.ps1 doctor`。只缺 Blender 不阻塞基础 GLB/OBJ；不要自动安装全部可选研究依赖或重跑论文实验。
4. 模型演示结果位于 `projects/onboarding-demo/viewer/scene.glb`，网页用 `?demo=1`；正式 `web/public/project.json` 不为演示覆盖。

## 真实新项目：只问一次最少信息

确认允许读取的输入目录、已知单位/坐标框架、目标走廊段和输出格式。已有信息不要重复问。未知但可从文件安全推断的信息先检查；不能推断的数据权限或坐标单位才向操作者提问。

先建独立项目目录，用 `Railway.ps1 new` 或既有 `railway_recon init`，再依照 `docs/QUICKSTART_CN.md` 完成输入审计与小样段。`new` 只建骨架，不能报告“模型生成成功”。

调用通用候选、TrackGraph、构件参数化与导出能力前阅读实际配置/CLI 帮助。已有 full-corridor 审计、replay 或报表生成不等于重新建模；只有确实生成新几何、注册资产并验证网页所加载的产物，才能说模型更新了。不要把演示里人工编写的站台/雨棚布局冒充真实数据自动提取。

## 默认执行方式：异常驱动，单人可用

- 环境、配置、文件存在性、网格/资产关联、重复运行校验和已提供报告的汇总由机器完成；不要增加逐图人工签字队列。
- 安全与完整性错误必须说明并停止受影响阶段：权限不明、输入破坏、坐标冲突、未知目录覆盖、模型缺失、版本错配。其余独立工作可以继续。
- 语义不确定、局部几何不完美或缺测区允许作为明确标记的候选，优先让用户看到模型并最后微调；不要将未验证候选写成 accepted/final，也不要通过删失败报告来“零失败”。
- 不为了所有一般性告警都为零而阻断整个出模。生产策略、精度定义和正式合同验收条件若需改变，必须明确说明，不能暗改阈值掩盖问题。
- 不要求用户具备多人角色或再找同事复核。旧 `NEW_PROJECT_CHECKLIST_CN.md` 只在需要正式验收时选用，不把它当日常操作工单。

## 更新与验证

运行本次修改相关测试；影响公共模块时再运行 `Railway.ps1 check`。检查退出码、实际产物和当前网页资源，不能只凭进程启动就报告成功。浏览器连接不可用时说明尚未视觉验证，不冒充已看过。

已生成演示的 manifest 绑定源码/依赖。修改相关源码后不要篡改 manifest 或覆盖旧结果：在新版本目录重新生成。若需要更新默认演示，先验证旧目录确为该工具生成且无用户新增文件，采用可恢复保留旧版的迁移方式；不得递归删除宽泛目录。必要时在新的源码副本重跑，无需让用户手工校验几十个文件。

启动端口被占用就选择明确的新端口，不杀用户现有服务。服务默认仅本机访问；启用外部模型目录时仅放行用户批准的专用模型目录，不放行整个磁盘、主目录或工作区。

## 数据与研究边界

真实点云、全景、坐标、台账、生产模型和构建后的私有网页资源不得进入公开仓库/论文附件。交接源码使用 `prepare_handoff_source.py` 的白名单副本，但仍不能凭文件后缀保证源码文本绝无秘密。不上传、不推送、不公开发布，除非本次得到明确授权。

研究结果保持已留存的限制：合成正式实验没有证实额外观测收益，公开数据语义映射和零命中案例尚存在问题。不要把工程交接成功包装为论文创新、现场精度或普遍自动重建已经成立。

完成后只交代：实际改了什么、模型/网页在哪里、哪些验证通过、仍有哪些真实限制。不要把可自动推进的步骤拆成下一轮让用户不断说“继续”。
